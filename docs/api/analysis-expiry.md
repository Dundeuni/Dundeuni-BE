# 검사 기록 보관 및 만료 데이터 실제 삭제

## 보관 기한

신규 IMAGE 분석의 expiresAt은 `ANALYSIS_RETENTION_SECONDS`로 계산하되 최대 30일(2592000초)이다.
1일 등 더 짧은 설정은 그대로 유지하며 30일 초과 설정만 30일로 제한한다.
설정값은 양의 안전 정수여야 한다. 환경변수 예시는 기존 86400초를 유지한다.
기존 행의 expiresAt을 변경하거나 앞으로 만료될 기존 기록을 30일 정책으로 소급 삭제하지 않는다.
이 보관 기간 생성 함수는 후속 분석 유형 저장 경로에서도 재사용할 수 있다.

## 자동 실제 삭제

`AnalysisExpiryCleanupService`가 서버 bootstrap 직후 한 번 실행하고, 이후 주기적으로 만료 기록을 정리한다.
조회 요청이 삭제를 촉발하지 않으며 별도 수동/관리자 HTTP 삭제 API는 추가하지 않는다.

- 주기: `ANALYSIS_CLEANUP_INTERVAL_MS`, 기본 60000ms(1분)
- 허용 범위: 1000~2147483647ms 정수. 잘못된 설정은 시작 시 오류
- 대상: 유형·사용자·진행 상태와 관계없이 `expiresAt <= 실행 시각`인 Analysis
- 배치 크기: 한 번에 최대 500건, 오래된 만료 시각과 ID 순
- 실제 삭제 시 부모 행에 저장된 요약·해시 등도 제거하고 기존 FK Cascade로 모델 결과 삭제
- 미만료 행과 그 모델 결과는 유지

조회에서는 expiresAt 경과 즉시 제외하지만 물리 삭제는 다음 정리 실행 때 이루어진다.
만료 기록이 500건보다 많으면 다음 실행에서 나머지를 처리한다. 서버 중지 기간이나 장애로 쌓인 기록은
재시작/DB 복구 후 후속 배치에서 처리하므로 만료 시각과 물리 삭제 시각은 완전히 같지 않다.

## 동시성·시간대·장애

PostgreSQL CTE와 단일 DELETE로 선별·잠금·삭제를 원자적으로 처리한다.
`FOR UPDATE SKIP LOCKED`로 다른 서버 인스턴스나 만료일 연장 작업이 잠근 행은 건너뛴다.
삭제에도 만료 조건을 적용하고, 같은 프로세스 안에서는 느린 작업이 중첩되지 않는다.
종료 시 타이머를 해제하고 진행 중인 정리 작업이 완료될 때까지 기다린다.

현재 Prisma DateTime은 UTC 값을 TIMESTAMP(3) WITHOUT TIME ZONE 컬럼에 보관하므로,
raw Date 매개변수는 `timestamptz AT TIME ZONE 'UTC'`로 명시적으로 변환해 비교한다.
실제 PostgreSQL의 UTC/Asia/Seoul 세션 모두에서 경계 동작을 검증한다.

DB 오류는 내부 연결 정보나 행 데이터를 출력하지 않고 고정 코드 `ANALYSIS_EXPIRY_CLEANUP_FAILED`만 기록한다.
실패하면 다음 주기에 다시 시도한다. 이미지 Provider나 Gemini는 호출하지 않는다.

## DB 및 검증

만료 조건과 정렬을 위한 `@@index([expiresAt, id])` 및
`20261122000000_analysis_expiry_index` migration을 추가했다. 기존 컬럼·Enum은 변경하지 않는다.
배포 환경에는 해당 migration을 적용해야 한다. 이 작업 중에는 테스트 전용 DB에만 적용했다.

새 scheduler의 주기·중복 실행 방지·종료·장애 후 재시도를 별도 테스트한다.
일반 API 테스트에서는 scheduler만 명시적으로 대체하여 백그라운드 삭제가 fixture와 경합하지 않게 하고,
실제 PostgreSQL 전용 스키마에서 다음을 검증한다.

- expiresAt 직전/동일/이후 경계 및 UTC/Asia/Seoul 시간대
- 만료 Analysis와 모델 결과의 실제 삭제, 미만료 다른 사용자 행·모델 보존
- 500건 배치 한도와 다음 실행의 잔여 처리
- 잠금/만료일 연장 중인 행 보존, 복수 인스턴스의 동시 실행
- 조회·삭제의 기존 보안 규약과 외부 AI 재호출 없음
- 신규 IMAGE 생성 시 최대 30일 기한 및 기존 IMAGE·검사 기록 회귀

기존 사용자 DB에 접속해 만료 데이터를 직접 삭제하지 않았다.
